# クロスレビュー（Claude × Codex）スキル

Claude が作った成果物（計画書・実装・PR差分）を、**別モデルを交えた二重レビュー**で客観視する。
狙いは著者バイアスの除去。真の独立性は「Claude 自身のレビュー」だけでは得られないため、
**Claude の独立レビューと Codex のレビューを二本立て**にすることが本スキルの肝。

> 前提: `codex` スキル（OpenAI Codex CLI 委譲）が使えること。未ロード／CLI不在なら
> §3 を飛ばし、Claude 単独レビュー（`/code-review`）にフォールバックする旨を人間に伝える。
> **採否とコミットは常に人間が決める。** 本スキルは修正を勝手に確定しない。

---

## 1. 対象の確定

引数が対象（PR番号・パス・ブランチ等）。省略時は作業ツリーの差分。
まず範囲を固定し、両レビュアーに**同一の対象**を渡せるようにする。

```powershell
git --no-pager diff --stat           # 変更範囲の把握
git --no-pager diff > "<scratchpad>\cross-review-diff.patch"   # 同一入力を固定
```

PR対象なら `gh pr diff <N> --repo <owner>/<repo>` を使い、同様に固定する。

---

## 2. Claude 独立レビュー

**`/code-review` スキルを使う**（自分のファイルを読み直すだけにしない）。
別コンテキストのレビュー用サブエージェントが走るため、著者バイアスが薄まる。
既定は medium。ロジックが重い／分岐が多い変更は `high` を指定。

結果を Claude 側の指摘リストとして控える（後で突き合わせる）。

---

## 3. Codex 並列レビュー

同一差分を **Codex に `--sandbox read-only` でレビューさせる**（編集はさせない）。
Codex は完了時に一括出力（途中出力なし）なので、**バックグラウンドで起動**して
§2 と並行させ、両方揃うのを待つ。

```powershell
codex exec --skip-git-repo-check --sandbox read-only `
  "この変更差分をレビューし、正しさに関わるbugを最優先で、次に簡潔化・効率の観点で指摘して。各指摘は file:line と根拠付きで。" `
  2>$null
```

- モデル／reasoning effort は `codex` スキルの手順に従って選ぶ（重い変更は `high`〜`xhigh`）。
- 追加観点で深掘りしたいときは `codex resume`（`echo "..." | codex exec --skip-git-repo-check resume --last 2>$null`）。
- `codex` 未ロード／CLI不在なら本ステップは省略し、その旨を明記して Claude 単独に切り替える。

---

## 4. 指摘の仕分け（共通／Codex固有／Claude固有）

両レビュアーの指摘を突き合わせ、3つに分類する。

| バケツ | 定義 | 既定の扱い |
| --- | --- | --- |
| **共通指摘** | 両者が挙げた（＝高確度） | 優先修正候補 |
| **Codex固有** | Codex のみ | §5 で裏取りが必要 |
| **Claude固有** | Claude のみ | §5 で裏取りが必要 |

同一箇所を別表現で指摘している場合は共通に寄せる。重複・言い換えは統合する。

---

## 5. 片側のみの指摘を裏取り（対称に）

**Codex固有・Claude固有のいずれも鵜呑みにしない。** 同じ基準で検証する
（「Codexだけ疑う」運用は偏るので不可）。

- **実コードで確認**: 指摘箇所を実際に読み、再現条件・影響範囲を特定する。
- **公式ドキュメントで確認**: API仕様・ライブラリ挙動が絡む指摘は WebFetch/WebSearch で一次情報を当てる。
- 裏が取れた指摘のみ「有効」とし、取れないものは「未確認（保留）」として区別する。
  false positive はその旨を残して却下する。

---

## 6. 提示 → 採否は人間

仕分けと裏取りの結果を、採否しやすい形で提示する。

- **提示フォーマット（推奨）**: 指摘ごとに `[バケツ] file:line — 要約 / 根拠 / 裏取り結果 / 推奨対応`。
- **重要度順**（正しさに関わる bug を上位）に並べる。
- 修正は人間の採否を待つ。採用分を適用したら、**差分を再度クロスレビュー**して収束させる
  （Codex は `codex resume` で継続可）。
- 恒久改善・スタイル等は、その場で直さず**別Issueに起票**して追跡してよい。
- **コミット/PRマージ/Issueクローズは人間が行う。** 指示があれば実施する。

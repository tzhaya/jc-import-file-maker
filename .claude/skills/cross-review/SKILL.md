# リスク対応レビュー

## モード

- `single`: 中リスクのPRを独立レビュアー一人が確認する。一回に絞る場合は実コードがあるPR時に置く。
- `cross`: 高リスクのPRをClaudeとCodexが独立に確認する。計画では設計の手戻りが大きい場合だけ使う。

計画をレビューしてもPRレビューは省略しない。
高リスクが試行Issueの過半になったら、`PR crossのみ`と`計画＋PR cross`へ分ける。

## 対象を固定する

レビュー前に差分または計画を一つの固定ファイルへ保存し、全レビュアーへ同じ内容を渡す。
対象が変わったら古い結果を流用しない。

```powershell
git --no-pager diff --binary > <scratchpad>\review.patch
```

PRでは`gh pr diff <number> --repo <owner>/<repo>`を使う。

## レビューする

Claudeの独立レビューとCodexのread-onlyレビューへ固定対象を渡す。
各指摘に重大度、位置、再現条件、影響、根拠、推奨対応を要求する。
正しさ、起動不能、データ破損、互換性、権限、非同期競合を優先する。

`cross`の結果は、共通、Claudeのみ、Codexのみに分類する。
片側だけの指摘は実コードで再現条件を確認し、仕様依存なら公式資料で裏を取る。
採否は人間へ委ねる。

局所修正なら関連テストだけを再実行する。
仕様、構造、共有境界、永続形式、権限、非同期設計、実行環境の前提を変えた場合だけ新しい固定差分を再レビューする。

# 現状レビュー（2026-07-05）

作成日: 2026-07-05（JST）

## 概要

2026-07-05 JST 時点のローカル確認では、このプロジェクトはかなり実用品に近い段階にある。

評価を一言でまとめると、**メタデータ作成・確認・TSV 生成の業務支援ツールとしては実用域。ただし、JAIRO Cloud への実インポート運用と完全自動化にはまだ検証・設計課題がある**。

## 進捗評価

主要フェーズはほぼ完了している。

- Crossref / JaLC / DataCite / OpenAlex / ROR / CiNii / KAKEN / OPF 連携
- JPCOAR 2.0 対応
- 複数 DOI 一括取得
- TSV 出力
- Chrome 拡張化
- Chrome Web Store 公開
- OpenAlex 機関別著作検索
- 登録済み照合バッジ
- DataCite DOI パスの OPF エンバーゴ判定

Chrome 拡張版は `1.19.0` で、DataCite DOI パスの OPF エンバーゴ判定まで反映済みである。

ローカルでは `npm test` が通過した。JSON 構文、JS 構文、UTF-8 妥当性、共有ファイル同期、TSV ヘッダー同期はいずれも PASS だった。

## 実用性

実用性は高い。特に Chrome 拡張版は、API キー管理、CORS 回避、JaLC / OPF / KAKEN 対応、サイドパネルでの複数ツール統合があり、通常ブラウザ版より業務投入しやすい構成になっている。

一方で、最大の注意点は README に明記されている通り、**インポート用 TSV 生成はできるが、実際の JAIRO Cloud インポートは未検証**という点である。

したがって、メタデータ作成補助・候補抽出・手元確認までは十分使えるが、機関リポジトリ本番登録フローに組み込むには、テスト環境での TSV インポート検証が必要である。

## 強み

- DOI 起点の対応範囲が広く、Crossref、JaLC、DataCite に対応済み。
- Chrome 拡張版の完成度が高く、CORS 制約 API を Service Worker 経由で扱える。
- OpenAlex 起点の候補発見から TSV 生成まで、手動運用版のパイプラインが形になっている。
- ドキュメントと変更履歴が丁寧で、保守者向けの知見も蓄積されている。
- `npm test` による最低限の品質ゲートがある。
- 過去のバグから、E2E、DOM 描画、拡張実機検証の限界まで文書化されている。

## 主な課題

### TSV 実インポート検証

本番実用化の最大関門である。生成 TSV が JAIRO Cloud のテスト環境でどこまでそのまま取り込めるかを確認する必要がある。

### Chrome 拡張限定機能の検証

標準版 E2E では OPF などの拡張限定機能を拾いきれない。Chrome 拡張の実機レビューを最終防衛線として扱う必要がある。

### コード重複・保守性

標準 HTML 版と Chrome 拡張版の二系統を維持している。`shared.js` などで共有化は進んでいるが、メインロジックにはまだ保守負荷が残っている。

### 権限・セキュリティレビュー

DOI 自動取得まわりの Chrome 権限、ページ由来データ検証、`optional_host_permissions` 周辺は引き続き優先度が高い。

### 永続的な処理状態管理

OpenAlex 候補の「処理済み」「除外済み」「登録済み」を長期管理する仕組みは未実装である。現状の登録済み照合は都度判定であり、ワークフロー全体の状態管理までは担っていない。

## 将来的な拡張可能性

一番有望なのは、OpenAlex 起点の登録候補発見をさらに伸ばす方向である。現在は「検索 → 選択 → DOI リスト投入 → TSV 生成」の手動運用版まで来ているため、次は以下が自然である。

1. **TSV インポート検証**
   JAIRO Cloud テスト環境で、生成 TSV がどこまでそのまま通るか確認する。これは以後の自動化の前提になる。

2. **SCPJ 連携**
   国内誌の OA ポリシー補完として有効である。OPF の国内版補完のような位置づけになる。

3. **リポジトリ JSON からの再インポート**
   既存レコードを編集・複製・差分更新する用途に広がる。

4. **異種アイテムタイプテンプレート対応**
   現状の「デフォルトアイテムタイプ（フル）」中心から、機関ごとの実テンプレートに合わせやすくなる。

5. **定期ハーベスタ化**
   OpenAlex Works API で自機関論文を定期取得し、候補リストを自動生成する方向。ただし、サーバーサイド化、API キー管理、永続ストア、重複排除、除外管理が必要になる。

6. **SWORD v3 連携**
   TSV + ZIP の手動アップロードを超えて、JAIRO Cloud への投入まで自動化する将来像。ただし、運用リスクが高いため、TSV 実インポート検証後が前提である。

## 総合評価

現在のプロジェクトは「試作」よりかなり先に進んでおり、**実務者がメタデータ作成を効率化する道具としてはすでに強い**。

次の壁は、機能追加そのものよりも、**本番登録フローでの検証、保守性、運用自動化、状態管理**である。
